# PPT 核心论点：为什么不是“Agent 群聊”

## 建议页标题

**完整时间线用于审计，受控路由用于协作**

## 页面正文

传统的多 Agent 群聊模式让所有节点读取完整历史、不断追加发言。它便于快速对话，却不适合工程协作中的私有上下文、专业分工和责任控制。

工程协同 Agent Relay 保留完整消息时间线，供总监和人工角色回放、追溯和审计；但每个 Agent 只收到 Relay 授权给它的任务与证据。Relay 同时控制一条消息的可见范围、接收角色与回复权限。

| 路由模式 | 典型用途 | SC 管壁核查示例 |
| --- | --- | --- |
| 定向 `direct` | 明确分工、专业核查 | 分别派给综合监控与通信专业 |
| 协同组 `group` | 共同前提、跨专业协调 | “照片对象类型尚未确认”人工纠偏 |
| 广播 `broadcast` | 已确认状态同步 | “事项已进入待总监确认” |
| 受限 `restricted` | 原始证据、内部意见 | 专业测量记录与内部核查材料 |

## 建议口播（20 秒）

> 我们不是让 Agent 在一个群里无限聊天。完整时间线用于审计，但协作时由 Relay 决定谁应该看见、谁可以回复、谁需要确认。专业任务可以定向派发，共同前提可以在协同组公开，原始证据仍保持受限可见。这样既能协同，也不会把每个人的上下文全部暴露出去。

## 观众应记住的一句话

**Relay 的价值不只是转发消息，而是把工程组织中的“可见性、分工和责任”变成可执行的协同规则。**
