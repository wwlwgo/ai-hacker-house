# 场景矩阵与扩展路线

## 1. 为什么不只准备一条场景

一条 SC 管专项核查已经足够做出完整 MVP，但它只证明“临时事项的并行核查”。若主链路稳定，第二条场景可以证明 Relay 不是为一件事量身定做，而是能支持周期性、跨渠道、多口径的工程信息流。

关键不是多做几个互不相干的 Demo，而是让多个场景复用同一套：

```text
事项 trace_id
消息契约
角色 Adapter
证据引用
轮次/状态控制
Human Adapter
报告或输出视图
```

## 2. 场景优先级

| 场景 | 类型 | 展示的核心能力 | 明天优先级 |
| --- | --- | --- | --- |
| A. SC 管专项核查 | 临时、并行 | 多专业取证、对象歧义、人工纠偏、结论汇聚 | P0，必须 |
| B. 安全日报协同 | 周期、汇总 | 施工日报与巡检事实合并、多口径输出、隐患闭环 | P1，有余力 |
| C. 86 盒点位核对 | 临时、并行 | 施工解释与 BIM/监理核查对照 | P2，只做 fixtures 或静态回放 |
| D. 周报/月报收集 | 周期、批量 | 缺件催收、台账更新、跨承包商确认 | 未来阶段，不进明天主线 |

## 3. 第二场景：安全日报协同

### 场景结构

```text
施工单位日报/照片进入
-> 安全专监 Agent 结合独立巡检记录补充事实
-> Relay 发现缺项或隐患，创建跟踪事项
-> Human Adapter 确认处置等级
-> 从同一事实生成：业主群报送草稿 + 正式日志草稿
```

### 为什么它与 SC 场景互补

| SC 管专项核查 | 安全日报协同 |
| --- | --- |
| 突发质疑驱动 | 每日周期驱动 |
| 多专业并行取证 | 来源信息与独立巡检合并 |
| 主要输出为专项报告 | 主要输出为不同口径的日报/日志 |
| 人工纠偏对象和标准 | 人工确认隐患等级和报送边界 |

### 严格边界

第二场景不做真实群消息导入、不做现场图片识别、不做正式上报。它只使用一组脱敏 JSON 事件，展示“同一事实 -> 两个不同输出视图”的信息流。

## 4. 如何接入现有工程 Skill

Skill 不是 Relay 的替代品，而是每个角色 Agent 的本地能力包。Relay 决定“什么时候找谁协作”；Skill 决定“这个角色收到任务后怎样稳定完成专业工作”。

| 现有能力方向 | 未来对应角色能力 | 在 Demo 中的体现 |
| --- | --- | --- |
| 方案复核与意见比对 | 专业核查 Agent | 结构化提交“结论 + 依据 + 待补项” |
| 工程联系单生成 | 监理/资料角色 | 退回或整改时可生成联系单草稿 |
| 监理工作报告 | 报告 Agent | 根据批准结论包生成专项报告草稿 |
| 集成管理例会纪要 | 汇总/资料角色 | 从多个结构化事项形成会议纪要或周报草稿 |

明天不需要真正接入全部 Skill。最合适的演示是把它们标为 Agent 的 `capabilities`，并选择其中一个报告类能力作为“已批准结论 -> 草稿”的输出。

## 5. 明天的扩展决策门

只有在以下全部满足时，才开启第二场景：

1. SC 管场景能从 `NEW` 稳定跑到 `REPORT_DRAFTED`。
2. 人工纠偏能触发第二轮定向澄清。
3. 至少一条结论能展示证据回溯。
4. 已完成一次三分钟完整演练。

若任一条件未满足，不做第二场景，改为在页面或 PPT 中展示“安全日报协同”的静态场景卡片与未来路线。

## 6. 六小时的合理工作量

主场景不是简单的消息列表。完整质量线包括：

```text
统一数据契约
-> 多角色路由
-> 两轮状态控制
-> 并行分支汇聚
-> 人工中途纠偏
-> 证据详情与审计回放
-> 权限控制
-> 报告草稿
-> Mock 降级
-> 观察面板与三分钟演练
```

三人协作下，P0 做扎实是合理的六小时工作量；第二场景、Skill 可视化和视觉打磨是有价值的扩展，而不是主链未完成时的填充工作。
