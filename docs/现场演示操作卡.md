# 现场演示操作卡

## 启动

```bash
cd /Users/wwl/Documents/Codex/ai-hacker-house
.venv/bin/python -m streamlit run streamlit_app.py
```

打开：`http://localhost:8501`

## 五步点击

| 点击 | 屏幕状态 | 一句话讲解 |
| --- | --- | --- |
| 重置案例 | `NEW / 新建事项`，`Round 0/2` | 每件跨角色事项先获得可追踪编号。 |
| 运行 Round 1 | `AWAITING_HUMAN_CORRECTION / 等待人工纠偏` | 两个专业节点并行提交初步证据，不直接形成最终结论。 |
| 人工纠偏 | `CLARIFICATION_REQUIRED / 需要定向澄清` | 人可在中途纠正错误前提，纠正进入审计链。 |
| 运行 Round 2 | `HUMAN_CONFIRMATION / 待总监确认` | 汇总节点给出证据包和拟定结论，仍须人工批准。 |
| 总监批准并生成报告 | `REPORT_DRAFTED / 报告草稿已生成` | 报告只使用已批准的事实和证据引用。 |

## 页面重点

- 顶部：事项、`trace_id`、轮次、状态和 Mock 标识。
- 左侧：各角色当前进度。
- 中部：同一事项的审计时间线；`[人工介入]` 和 `[待人工确认]` 是关键转折点。
- 右侧：证据引用、拟定结论和审批后才出现的 Markdown 报告。

## 故障降级

若网页无法展示，运行：

```bash
python3 scripts/run_demo.py
```

终端会输出相同的状态推进、结构化消息、证据引用和报告草稿。

这是本地 Mock 节点和脱敏演示数据，不接入微信、飞书、钉钉、邮件、真实 Agent、真实项目资料或真实 LLM。它不自动签发、盖章或正式发送；专业判断与最终责任仍由人承担。
