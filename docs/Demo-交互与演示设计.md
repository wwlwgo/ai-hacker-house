# Demo 交互与演示设计

## 1. 展示定位

页面不是新的聊天工具，也不是完整企业项目管理系统。它是一块本地“协同指挥台”：让观众看见同一工程事项在不同角色之间如何流转、何时需要人介入、每个结论依据什么证据。

建议明天使用 Streamlit 做本地浏览器观察面板。Streamlit 是 Python 的快速界面工具：运行 Python 程序后会生成一个本地网页，适合展示卡片、按钮、表格、时间线和 Markdown 预览，不需要单独写前端 JavaScript。

若没有时间完成网页，CLI 输出或 Markdown 时间线是完整降级方案；Relay 核心不依赖界面。

## 2. 页面线框图

```text
┌──────────────────────────────────────────────────────────────┐
│ 工程协同 Agent Relay                                         │
│ 事项：专项核查              状态：待总监确认   当前轮次：2/2 │
├──────────────┬──────────────────────┬────────────────────────┤
│ 角色状态     │ 协同消息时间线        │ 结论与证据             │
│              │                      │                        │
│ 业主：已发起 │ R0 创建事项           │ 已确认事实             │
│ 综合监控：已答│ R1 并行专业核查       │ - 实测记录             │
│ 通信：已答复 │ 人工：对象纠正         │ - 适用依据             │
│ 总监：待确认 │ R2 定向澄清           │                        │
│              │ 汇总：建议结论         │ 证据卡片               │
│              │                      │ [测量] [条款] [台账]  │
├──────────────┴──────────────────────┴────────────────────────┤
│ Human Adapter                                                  │
│ [运行下一轮] [查看证据] [人工纠偏] [批准并生成报告]           │
├──────────────────────────────────────────────────────────────┤
│ 报告草稿预览：仅在总监批准后显示                               │
└──────────────────────────────────────────────────────────────┘
```

## 3. 四个必需交互

| 交互 | 页面动作 | 系统变化 | 观众应理解的价值 |
| --- | --- | --- | --- |
| 运行下一轮 | 点击后处理下一组预置消息 | 轮次、状态和时间线推进 | 协作是受控流程，不是无限聊天 |
| 查看证据 | 先选择某条结论或证据卡片，再查看详情 | 展示来源说明与关联消息 | 结论能回溯，不是模型随口生成 |
| 人工纠偏 | 输入或选择一条纠正 | 旧前提标记失效，Relay 发起定向澄清 | 人可随时进入协作通道，不只在最后审批 |
| 批准并生成报告 | 总监点击批准 | 状态转为已批准，显示报告草稿 | 正式责任保留给人，Agent 只做草稿 |

## 4. 可选交互

- 查看不同角色的 Inbox/Outbox。
- 按 `trace_id` 回放某个事项。
- 切换“Mock 模式”标识，说明无网络情况下仍可演示相同协议。
- 展开“缺失证据/冲突”说明。

这些功能只在主链路稳定后再做。

## 5. CLI / Markdown 降级展示

若 Streamlit 未完成，使用一个结构清晰的终端或 Markdown 时间线：

```text
[R0] owner_adapter -> relay : issue.created
[R1] relay -> integrated_monitoring : verification.requested
[R1] relay -> communications : verification.requested
[R1] integrated_monitoring -> relay : evidence.submitted
[R1] communications -> relay : evidence.submitted
[H]  director_human -> relay : human.correction
[R2] relay -> specialists : clarification.requested
[R2] reconciler -> director_human : conclusion.proposed
[H]  director_human -> relay : human.approval
[END] report_agent : report.drafted
```

随后显示：当前状态、建议结论、三条证据引用和报告草稿标题。这样即使页面没有完成，Demo 的技术论点仍然成立。

## 6. 界面约束

- 不做多窗口聊天气泡堆叠，不伪装成微信或企业 IM。
- 不展示真实项目、人员、群组、电话或受限附件。
- 不显示“自动签发”“自动对外发送”等越权动作。
- 所有自动结论应标为“建议”或“待人工确认”。
- 用状态、角色、轮次、证据和审批作为主视觉，不用大段模型生成文字占满屏幕。
