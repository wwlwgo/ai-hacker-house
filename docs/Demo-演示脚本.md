# Demo 演示脚本

建议时长：3 分钟。只演示一个脱敏事项，不展示第二场景或外部系统。

## 开场前

- 启动：`.venv/bin/python -m streamlit run streamlit_app.py`
- 打开：`http://localhost:8501`
- 点击“重置案例”，确认顶部为 `NEW / 新建事项`、`Round 0/2`。
- 页面应显示 `Mock nodes / anonymized demo data`。若本机 `.env` 配置了 `DEEPSEEK_API_KEY`，最后一步会尝试用真实 LLM 起草报告；否则或请求失败时自动显示 `Mock 回退`。

## 1. 事项进入（20 秒）

**屏幕**：顶部事项栏、角色轨道和 Round 0 的 `issue.created`。

**讲解**：

> 工程现场的一条质疑通常要跨专业转发、补充证据、再由负责人汇总。单个 Agent 可以帮一个人写材料，但不能天然管理跨角色的任务、证据和责任链。这里先把它变成一个有 `trace_id` 的事项。

## 2. Round 1 并行专业核查（35 秒）

**动作**：点击“运行 Round 1”。

**屏幕**：状态变为 `AWAITING_HUMAN_CORRECTION / 等待人工纠偏`；时间线出现两条 `verification.requested` 和两条 `evidence.submitted`；两个专业角色显示“初步证据已提交”。

**讲解**：

> Relay 向综合监控和通信两个专业节点定向派发任务。它不要求节点使用同一种 Agent，只要求回传同一类结构化结果：专业判断、证据引用和仍待澄清的前提。

## 3. Human Adapter 中途纠偏（35 秒）

**动作**：点击“人工纠偏”。

**屏幕**：状态变为 `CLARIFICATION_REQUIRED / 需要定向澄清`；时间线前部出现 `[人工介入]`；页面显示预设纠偏文案。

**讲解**：

> 这里不允许 Agent 自己一路对话到最后。专业人员或总监可以在中间纠正对象、标准或事实前提。这条人工消息进入同一审计链，并让第一轮的初步判断不能直接作为最终结论。

## 4. Round 2 证据汇聚（40 秒）

**动作**：点击“运行 Round 2”。

**屏幕**：状态变为 `HUMAN_CONFIRMATION / 待总监确认`；时间线出现 `[待人工确认]`；右侧出现已确认事实、拟定结论和证据引用；报告草稿尚未出现。

**讲解**：

> 第二轮只向受影响的两个专业角色补充对象识别和适用依据。汇总节点输出的是证据包和拟定结论，不是自动签发的结论。现在系统明确停在总监确认前。

## 5. 总监确认与报告草稿（35 秒）

**动作**：点击“总监批准并生成报告”。

**屏幕**：状态变为 `REPORT_DRAFTED / 报告草稿已生成`；右侧显示来源为“真实 LLM”或“Mock 回退”，并出现 Markdown 报告草稿，其中包含已确认事实、已批准结论和证据引用。

**讲解**：

> 自动化在这里做的是信息整理、证据汇聚和草稿生成。最终批准仍由人承担，报告节点只读取已经批准的结论包，不读取未经确认的早期消息。网络或模型失效时，Mock 草稿会接手，协同链本身不会中断。

## 收尾（15 秒）

**讲解**：

> 今天的 Demo 用本地 Mock 节点验证协同协议和人工控制。未来不同人仍可使用 Codex、TRAE、Hermes 或人工方式处理本地资料；当事项需要跨角色协作时，再通过 Adapter 接入同一条可审计的 Relay 消息链。

## 降级展示

若 Streamlit 页面无法启动，运行：

```bash
python3 scripts/run_demo.py
```

它会在终端展示相同的 `trace_id`、状态、13 条结构化消息、拟定结论、证据引用和 Markdown 报告草稿。
