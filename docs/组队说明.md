# 工程协同 Agent Relay：组队说明

## 一句话

把工程项目中散落在不同群组、不同角色和不同通用 Agent 里的任务、证据与结论，变成一条可追溯、可人工介入的协同消息链。

## 真实痛点

在工程项目里，同一份现场事实常被不同人、不同专业、不同上报口径反复转发和重组。今天每个人都可以用通用 Agent 写报告、审查文件，但跨单位协作仍主要靠群消息、邮件和人工催办：谁回复了、依据是什么、是否需要补充、最终谁确认，常常要靠人回头翻记录。

我们不想再造一个通用聊天工具。我们想验证一个更贴近真实组织协作的范式：每个人继续使用自己喜欢的 Agent 或人工方式处理本地资料，协作时通过统一 Relay 交换结构化的任务、证据和结论。

## 明天要做的 MVP

使用脱敏的“SC 管壁厚专项核查”案例，演示：

```text
业主质疑
-> Relay 建立事项
-> 综合监控与通信两个专业并行核查
-> 专业节点提交不同来源的证据
-> 人工中途纠正对象或标准的歧义
-> Relay 定向追问并汇聚结论
-> 总监确认
-> 生成专项汇报草稿
```

展示重点不是大模型的文笔，而是：不同角色如何在统一事项下协作，如何控制轮次，如何保留证据，如何让人随时纠偏。

## 明确不做

- 不接真实微信、飞书、钉钉、邮件或企业系统。
- 不要求每个参与者使用同一种 Agent。
- 不处理真实项目原始资料、真实群成员或真实联系方式。
- 不做电子签章、正式外发、完整权限系统或生产级 A2A 兼容。
- 不让 Agent 自动作出正式审批、停工或签发决定。

## 希望寻找的队友

**Agent/后端伙伴**：愿意用 Python 快速实现结构化消息、状态机、Mock 节点和可选模型 Adapter。

**前端/产品伙伴**：愿意把消息时间线、证据引用、角色状态和人工确认做成简洁的本地观察面板。

没有前端伙伴也可以完成 Demo：先用 CLI 或 Markdown 时间线展示同一条消息、证据和审批链，观察面板只是在主链路完成后的增强项。

**领域与 Demo 负责人**：我负责真实场景、角色边界、验收判断、脱敏样例和最终路演。

## 可拆分分工

| 模块 | 内容 | 适合的伙伴 |
| --- | --- | --- |
| Relay Core | 消息模型、路由、轮次、状态机、SQLite 审计 | Python / Agent Builder |
| Agent Adapter | 两个专业 Mock Agent、汇总 Agent、可选 LLM 接口 | Python / LLM Builder |
| 观察面板 | 状态卡、时间线、证据详情、人工操作 | Streamlit / 前端 / 产品 |
| Demo 与路演 | 脱敏材料、专业规则、脚本、Q&A | 我主导，可共同打磨 |

## 30 秒组队话术

我做工程项目管理，真实痛点不是单份文件怎么让 AI 写得更快，而是跨专业、跨单位的信息还在群里不断转发、补资料和重新整理。明天我想做一个工程协同 Agent Relay：每个人保留自己的 Codex、TRAE、Hermes 或人工工作方式，但协作事项通过统一消息链分派任务、回传证据、允许人工纠偏，最后形成可追溯结论。我已经准备好一个脱敏的专项核查场景和消息协议，想找一位能做 Python Agent/后端的伙伴，以及一位能做清晰观察面板的伙伴。
