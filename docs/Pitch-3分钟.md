# 工程协同 Agent Relay：3 分钟路演稿

大家好，我带来的项目叫“工程协同 Agent Relay”。

在工程项目里，越来越多的人开始用通用 Agent 写日报、审查方案、整理台账、生成汇报。它们确实提升了个人效率。但项目里真正耗时的部分，经常发生在多人协作时：同一件现场事项在不同群组反复转发，多个专业补照片、找依据，最后负责人再从聊天记录里重组结论。

这不是某一个 Agent 不够聪明，而是缺少一层让不同角色协作的机制。

我们不要求所有人改用同一种 Agent。有人可以使用 Codex，有人使用其他工具，也有人仍然人工处理资料。我们的设想是：当信息需要跨角色流转时，把它转换为统一的协同消息。每条消息都带有事项编号、发送角色、接收角色、当前轮次、证据引用和人工确认要求。Agent Relay 负责路由、控制轮次和保留审计链，但不替代专业人员和负责人的责任。

今天展示的是一个脱敏的专项核查场景。发起方对现场管材壁厚提出质疑后，Relay 同时向综合监控和通信两个专业节点派发核查任务。两个节点分别返回模拟的专业证据和依据引用。

这里的关键不是让两个 Agent 无限聊天。页面会展示完整时间线，目的是让负责人审计和回放；实际协作中，Relay 可以按角色定向路由，原始资料仍归各自角色管理。

接着，总监通过 Human Adapter 插入一条纠偏：照片对象和适用标准尚未确认，第一轮结论不能直接作为最终判断。Relay 因此只向受影响的专业节点发起第二轮澄清。第二轮证据齐全后，汇总节点形成“拟定结论”和证据包，系统明确停在“待总监确认”。

只有总监批准后，报告节点才会根据已批准的结论包生成 Markdown 草稿。也就是说，自动化做的是任务推进、信息整理、证据汇聚和草稿生成；人仍然可以观察、补充、纠偏、暂停和批准。

这次 Demo 使用本地 Mock 节点和脱敏数据，没有宣称已经接入微信、飞书、真实模型或真实项目资料。它验证的是一个可扩展的协同范式：未来每个组织或角色都可以保留自己的 Agent 和上下文，通过 Adapter 接入同一条可追溯、可人工控制的工程协同消息链。

工程协同 Agent Relay，让同一件工程事实不再在不同群里断裂，而是形成一条可追踪、可干预、可承担责任的协同链。
