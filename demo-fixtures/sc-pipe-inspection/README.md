# 脱敏案例：专项管材壁厚核查

## 1. 用途与边界

本目录只包含黑客松 Demo 的虚构、脱敏材料，用于验证工程协同 Agent Relay 的消息协议。它不对应任何真实项目、人员、单位、群组、文件编号或现场照片。

`SC` 只是演示标签；目录中的数值、技术要求和结论均为虚构示例，不能作为任何真实工程的规范依据。

场景保留真实工程协作的结构特征：对象存在歧义、多专业并行核查、证据来源不同、人工中途纠偏、结论需经负责人确认。

## 2. 故事线

一位发起方对现场照片中的管材壁厚提出质疑，要求项目团队核查对象类型、实测情况和适用要求。

Relay 创建 `sc-pipe-001`，将任务并行发给两个专业节点：

```text
综合监控专业：核对现场测量记录与该专业依据。
通信专业：核对专业台账与对应的技术要求。
```

第一轮后，Human Adapter 指出照片对应对象的类型尚未确认，原有判断不能直接作为最终结论。Relay 发起第二轮定向澄清。两个专业节点补充对象识别和适用依据后，汇总节点形成建议结论；负责人确认后，报告节点生成草稿。

第一轮的所有专业回复均为“初步核查结果”，不能直接进入报告，也不能跳过对象确认和负责人批准。

## 3. 角色上下文边界

| 角色 | 可见的模拟上下文 | 不可见内容 |
| --- | --- | --- |
| 综合监控 Agent | 模拟测量记录、模拟专业条款摘要 | 通信专业原始台账 |
| 通信 Agent | 模拟抽检台账、模拟专业条款摘要 | 综合监控测量细节 |
| 汇总 Agent | 两个专业节点返回的结构化结果 | 各节点未提交的私有资料 |
| 总监 Human Adapter | 完整审计链、建议结论 | 不自动生成或修改专业证据 |
| 报告 Agent | 已批准的结论包 | 未确认的早期聊天或被否定前提 |

## 4. 模拟证据清单

| 证据 ID | 类型 | 内容说明 | 初始可见角色 |
| --- | --- | --- | --- |
| `ev-photo-description-01` | 图片说明 | 一张现场管材照片的脱敏文字描述 | 发起方 |
| `ev-measurement-01` | 测量记录 | 模拟的壁厚测量读数与取样说明 | 综合监控 |
| `ev-integrated-clause-01` | 条款摘要 | 模拟的综合监控专业技术要求摘要 | 综合监控 |
| `ev-communications-check-01` | 台账摘要 | 模拟的通信专业抽检结果 | 通信 |
| `ev-communications-clause-01` | 条款摘要 | 模拟的通信专业要求摘要 | 通信 |
| `ev-object-confirmation-01` | 澄清记录 | 对照片对象类型的模拟确认说明 | 两个专业 |

所有证据均为演示性摘要，不代表真实工程标准或技术结论。

## 5. 预期消息序列

```text
1. issue.created
   发起方 -> Relay：提出现场管材壁厚核查请求。

2. verification.requested x2
   Relay -> 综合监控 Agent；Relay -> 通信 Agent。

3. evidence.submitted x2
   两个专业节点分别提交初步测量/台账与依据。

4. human.correction
   专业人员或总监代表指出：照片对象类型尚未确认，不能直接得出最终结论。

5. clarification.requested x2
   Relay 仅向受影响的两个专业节点发起第二轮澄清。

6. evidence.submitted x2
   两个专业节点补充对象识别与适用依据。

7. conclusion.proposed
   汇总 Agent 输出事实、证据、冲突状态和建议结论。

8. human.approval
   总监 Human Adapter 批准，或选择退回补充。

9. report.drafted
   报告 Agent 只使用已批准结论包生成 Markdown 草稿。
```

## 6. Demo 要证明什么

- 不同专业节点可以使用不同资料和不同 Agent 实现，但通过同一消息契约协作。
- Relay 控制轮次，避免无休止的 Agent 对话。
- 人能在中途纠正错误前提，并使受影响结论重新核查。
- 结论必须关联证据；缺少证据时应进入“证据不足”而不是自动闭环。
- 报告草稿只能在负责人确认之后生成。
