# 脱敏案例：安全日报协同

## 1. 用途

本场景是工程协同 Agent Relay 的第二条演示线。它不对应真实项目，不代表真实安全规范、隐患等级或对外报送要求。它用于证明同一套 Relay 协议不仅能处理临时专项核查，也能处理周期性信息收集、多口径输出和闭环跟踪。

只有 SC 管主场景稳定完成后，才实现本场景的运行逻辑；否则它仅作为静态案例卡片和未来扩展说明。

## 2. 故事线

施工单位通过一个模拟来源 Adapter 提交当日施工摘要、人员信息和现场照片说明。安全专监 Agent 同时提交独立巡检记录，指出某作业面存在需要跟踪的问题。两份信息对同一作业面的描述不完全一致。

Relay 创建 `safety-daily-001`：

```text
施工日报进入
-> 安全专监补充独立巡检事实
-> Relay 标记两份信息的差异
-> Human Adapter 确认处置级别和是否需要跟踪
-> 形成统一的当日事实包
-> 生成两个不同口径的草稿：沟通版日报、归档版安全日志
```

## 3. 与主场景的区别

| 专项核查 | 安全日报协同 |
| --- | --- |
| 临时事项 | 每日周期事项 |
| 两专业并行取证 | 来源日报与独立巡检合并 |
| 核心风险是对象/标准歧义 | 核心风险是遗漏、差异和状态过期 |
| 一个专项汇报草稿 | 两个不同口径的日报草稿 |

## 4. 角色与输出

| 角色 | 提交内容 | 输出权限 |
| --- | --- | --- |
| 施工方 Human/Agent Adapter | 模拟施工摘要、照片说明、待协调事项 | 仅提供来源材料 |
| 安全专监 Agent | 模拟巡检记录、问题、处置建议 | 形成专业建议 |
| Relay | 差异识别、缺项提示、事项路由 | 不作正式处置决定 |
| 总监 Human Adapter | 确认处置级别、退回或批准 | 唯一批准节点 |
| Report Agent | 基于批准事实生成两份草稿 | 不可跨过批准门 |

## 5. 预期消息序列

```text
1. daily_report.submitted
   施工方 -> Relay：提交模拟施工摘要和证据说明。

2. inspection.submitted
   安全专监 -> Relay：提交独立巡检事实和问题建议。

3. discrepancy.detected
   Relay：标记同一作业面描述不一致或缺失内容。

4. human.classification
   总监或专业负责人：确认处置级别、是否进入跟踪。

5. daily_fact_pack.approved
   Relay：形成已批准的当日事实包。

6. report.drafted x2
   Report Agent：生成沟通版日报草稿和归档版安全日志草稿。
```

## 6. 要展示的价值

- 施工方来源信息不能直接作为监理对外结论。
- 独立巡检记录可以与来源材料并列、对照和追溯。
- 同一份经过确认的事实可生成不同报送口径，不再手工复制重写。
- 高风险或未确认问题不会因日报生成而被自动“闭环”。
